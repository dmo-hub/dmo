GGoal

poster-studio ผลิตโปสเตอร์โฆษณา (PNG ใน dist/) — ต้องการระบบหลังบ้านแยก ที่คุมว่ารูปไหน approve ขึ้นเว็บ dmo ได้ และขึ้นหน้าไหน (แทรกใน index / decks / digimon / seals … ที่มีอยู่ — ไม่สร้างหน้า gallery ใหม่). หลังบ้านเป็น standalone HTML เปิดจากไฟล์ตรง ๆ ตาม pattern tools/curate.html ที่พิสูจน์แล้วใน repo นี้ + script publish ที่ idempotent.

AArchitecture — 3 ระบบแยก git

dmo/                          ← git #1 (เว็บ GitHub Pages)
├── docs/                     ← หน้าเว็บ publish
│   └── img/posters/          ← รูปที่ approve แล้ว (publish โดย script)
├── poster-studio/            ← git #2 (โรงงานผลิตโปสเตอร์ — ไม่แตะ)
│   └── dist/*.png            ← source รูปทั้งหมด
└── backoffice/               ← git #3 ใหม่ (ระบบหลังบ้าน)
    ├── backoffice.html       ← UI คุม approve + เลือกหน้า (เปิด file:// ตรง ๆ)
    ├── data/placements.json  ← manifest = source of truth
    ├── scan_posters.py       ← สแกน dist/ → เติมรูปใหม่เข้า manifest
    └── publish_posters.py    ← copy รูป approve + แทรก section ลงหน้าเว็บ
Flow: export poster ใน studio → scan_posters.py เจอรูปใหม่ → เปิด backoffice.html ติ๊ก approve + เลือกหน้า/ตำแหน่ง → Download JSON ทับ manifest → publish_posters.py → review git diff ใน dmo → commit/push เอง (ตาม policy)

DData model — placements.json

{
  "pages": ["index.html", "decks.html", "digimon.html", "seals.html", "system.html"],
  "posters": [
    {
      "id": "dungeon-kaiser",                      // = ชื่อไฟล์ ไม่มีนามสกุล
      "src": "poster-studio/dist/dungeon-kaiser.png",
      "added": "2026-07-16",                       // วันที่ scan เจอ
      "approved": true,                            // false = ห้ามขึ้นเว็บ
      "caption": "รับเซอร์วิส Kaiser's Lab",        // ข้อความใต้รูป (ว่างได้)
      "link": "",                                  // คลิกรูปแล้วไปไหน (ว่าง = ไม่ลิงก์)
      "placements": [
        { "page": "index.html",  "slot": "bottom" },   // top = ใต้ hero, bottom = ท้ายหน้า
        { "page": "system.html", "slot": "top" }
      ]
    }
  ]
}
  • scan เก็บทุกรูป, default approved:false — รูปใหม่ไม่มีทางหลุดขึ้นเว็บเองจนกว่าจะติ๊กใน UI
  • รูปเดียวขึ้นได้หลายหน้า (placements เป็น array)
  • scan ซ้ำไม่ทับ curation เดิม (merge by id — pattern เดียวกับ enrichers ของ dmo)

BBuild steps

1scan_posters.py (backoffice/)
  • glob poster-studio/dist/*.png → เทียบกับ manifest → เติมเฉพาะ id ใหม่ (approved:false)
  • รายงานรูปที่หายจาก dist แต่ยังอยู่ใน manifest (ไม่ลบเอง — แจ้งเฉย ๆ)
  • UTF-8 stdout ตาม convention dmo (path มีอักษรไทย)
2backoffice.html (standalone file:// — pattern curate.html)
  • drag-drop placements.json → grid รูป preview (โหลดรูปด้วย relative path ../poster-studio/dist/…)
  • ต่อรูป: toggle approve / เลือกหน้า + slot (checkbox ต่อหน้า, top·bottom) / แก้ caption·link
  • filter: ทั้งหมด · approve แล้ว · ยังไม่ approve · รูปใหม่
  • ปุ่ม Download JSON save กลับทับ manifest — ไม่มี server, ไม่มี dependency
3publish_posters.py (backoffice/ — idempotent)
  • copy รูป approved:true → dmo/docs/img/posters/<id>.png — ลบรูปใน posters/ ที่ไม่ approve แล้ว
  • แทรก section ต่อหน้า ด้วย marker guard <!-- POSTERS:<slot>:START --> … END --> (pattern ST-marker ของ build_seal_tables.py) — รันซ้ำ = แทนที่ block เดิม, ไม่ accumulate
  • slot top = หลังปิด .hero, slot bottom = ก่อน <footer>/ท้าย body — หน้าไหนไม่มี placement = ถอด block ออกเกลี้ยง
  • markup ใช้ class เดิมของ site (.card + site.css) — ไม่ inline CSS ใหม่ ตาม convention dmo
  • ผ่าน tools/validate.py (HTML balance + idempotency) ได้
4เอกสาร + git
  • backoffice/README.md — flow 4 ขั้น + คำสั่ง
  • dmo/.gitignore เติม backoffice/ (กันซ้อน git เหมือนที่ poster-studio ควรถูก ignore) — ตรวจก่อนว่า ignore poster-studio อยู่แล้วหรือยัง
  • git init ใน backoffice/ — รอ user สั่ง (ตาม git policy)

Xไม่ทำในรอบนี้

  • โพสต์ FB อัตโนมัติ / เชื่อม social API
  • แก้อะไรใน poster-studio (โรงงานผลิตอยู่ดีแล้ว)
  • server backend / database — GitHub Pages เป็น static, manifest JSON พอ
  • auto-commit / auto-push — user review diff เองเสมอ
