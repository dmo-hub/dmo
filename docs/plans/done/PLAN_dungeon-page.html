GGoal

เพิ่มหน้า docs/dungeon.html ในเว็บ DMO Tracker — รวมข้อมูลดันเจี้ยน (Dungeon Raid / ดันบอส) ที่ scrape จากทั้ง 3 เซิร์ฟ NA · KR · TH ให้ดูชื่อดันเจี้ยน · boss · วัตถุดิบ/ของดรอป ต่อเซิร์ฟ ในตารางเดียว แบบ cross-server (pattern เดียวกับ seals.html / lookup.html ที่มีอยู่). หน้าต้องdata-driven ผ่าน pipeline มาตรฐานของ repo (fetch→cache→scan→data/*.json→build) ไม่ hardcode — เพื่อผ่าน tools/validate.py (idempotent + JSON check).

AArchitecture — ตาม pipeline เดิม

fetchers/fetch_dungeons_*.py  →  cache/*.html  →  scanners/scan_dungeons.py
                                                          │
                                                          ▼
                                              data/dungeons.json  (source of truth)
                                                          │
                                                          ▼
                              builders/build_dungeon_html.py  →  docs/dungeon.html
                                                          │
                                                          ▼
                                    + link เข้า docs/index.html hub + nav ทุกหน้า

data/dungeons.json shape (cross-server, 1 entry/ดันเจี้ยน จับคู่ด้วยชื่อ/keyword เหมือน enrich kr/th): 

{
  "fetched_at": "YYYY-MM-DD",
  "dungeons": [
    { "id": "kaisers-lab",
      "boss_en": "Kimeramon",
      "na": { "name": "...", "mat": "...", "drop": "...", "src": "url" },
      "kr": { "name": "...", "mat": "...", "drop": "...", "src": "url" },
      "th": { "name": "...", "mat": "...", "drop": "...", "src": "url" } },
    …
  ]
}

BBuild steps

1 · fetchers/ — scrape ดันเจี้ยนต่อเซิร์ฟ → cache/
NA = dmowiki.com (ผ่าน fetch_via_cdp.py เดิม — ต้องเปิด Chrome debug port + solve CAPTCHA มือ) · KR = board (pattern fetch_kr_news_index) · TH = vplay.in.th (pattern fetch_th_patch_index)
2 · scanners/scan_dungeons.py — parse cache → จับคู่ 3 เซิร์ฟด้วยชื่อ boss/keyword → เขียน data/dungeons.json (offline, ไม่แตะเน็ต)
3 · builders/build_dungeon_html.py — gen docs/dungeon.html เต็มจาก json (idempotent) — nav + hero + ตาราง cross-server ใช้ css/site.css เดิม + inline <style> เฉพาะหน้าแบบ nametag
4 · index hub + nav — เพิ่ม feature card ใน docs/index.html + ลิงก์ Dungeon ใน nav ทุกหน้า (หรืออย่างน้อย index)
5 · validate — รัน python tools/validate.py ให้ผ่าน (JSON ครบ + tag สมดุล + build ซ้ำไม่มี diff)

?ต้อง confirm ก่อนลุย

Q1 URL หน้าดันเจี้ยนเป๊ะ ๆ ของแต่ละเซิร์ฟ — repo มี base (dmowiki / vplay) แต่ยังไม่รู้ path หน้า "Dungeon" ของแต่ละที่. ต้องได้ URL จริง 3 ตัว.

Q2 dmowiki = manual step — scrape สดอัตโนมัติเต็มไม่ได้ (Cloudflare + CAPTCHA). ยอมรับ workflow ที่ต้องเปิด Chrome debug + แก้ CAPTCHA มือตอน fetch NA ไหม?

Q3 fallback — ถ้าเซิร์ฟไหนหาข้อมูลไม่ครบ ใช้ 6 ดันจาก poster-studio/poster.json (boss/mat/drop มีอยู่) เป็น seed คอลัมน์ TH ก่อนได้ไหม?
